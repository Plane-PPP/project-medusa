# План прототипа: этаж башни

Статус: **план, ничего не реализовано.** Не выполнялись ни сборка, ни запуск. Ожидает согласования пунктов из
раздела «Решения перед стартом».

Основание: [Amber Island](amber-island-development-workflow.md), [аудит редактора](openyamm-level-editor-capabilities.md),
[инструкция](custom-indoor-level-workflow.md).

## Выбор инструментов

| Вариант | Настройка | С нуля | Редактирование | Автоматизация | Потери при обмене | Linux / Windows | Доработки | Оценка |
|---|---|---|---|---|---|---|---|---|
| **A. Blender → GLB → компилятор OpenYAMM** | Сборка редактора и инструментов, Blender | Да | Реимпорт по именам узлов | Полная (CLI, YAML, сценарии) | Нет промежуточного формата | Оба | Шаблон сцены, проверка UV, документация | **Рекомендуется** |
| B. Blender → MMEditor → BLV → OpenYAMM | `mm7.exe` + патч GrayFace + MMExtension, Windows | Да | Свойства граней теряются при реимпорте | Нет (GUI внутри игры) | Двери и события надо переносить в `scene.yml` и Lua; ODM читается неверно | Только Windows (Wine не проверялся) | Исправить детекцию ODM v7, конвертер DLV → `scene.yml` | Только для изучения чужих карт |
| C. Только редактор OpenYAMM | Сборка редактора | Indoor: нет (нет New Indoor Map, нет моделирования) | Да, для сцены | Частично | — | Оба | Создание пустой indoor-карты | Дополняет A: сущности, свет, события |

Вариант B не самый быстрый: он требует отдельной Windows-установки MM7 и даёт файлы, которые потом всё равно нужно
переводить в формат сцены OpenYAMM. Вариант A использует уже существующий конвейер, через который OpenYAMM собирает
indoor-карты MM9 (`tools/mm9_compile_indoor_source_main.cpp`), и не зависит от старых инструментов.

**Первый прототип:** A, геометрия из скрипта или Blender, сцена по шаблону, события вручную.
**Долгосрочно:** A + C. Blender отвечает за архитектуру, редактор OpenYAMM за сущности, свет и события, отдельный
редактор диалогов работает с YAML/Lua (см. ниже).

## Итерация 1: две комнаты и дверь

Образец по размерам: `doortest.blv` из Amber Island (2 комнаты, 1 портал, сдвижная дверь +X 368, скорость 50).

| Шаг | Результат | Критерий |
|---|---|---|
| 1. Сборка `mm9_compile_indoor_source`, `openyamm_indoor_source_tests`, редактора | Бинарники | 21 юнит-тест компилятора проходит |
| 2. `tower1.glb`: `ROOM_west`, `ROOM_east`, `ROOM_passage`, 2 портала, `MECH_door`, `TRIGGER_door`, `SPAWN_start` | GLB в отдельной папке прототипа | Импорт без «Unclassified» предупреждений |
| 3. `tower1.geometry.yml` + `tower1.scene.yml` + `tower1.lua` | Исходники карты | Компилятор пишет BLV: 3 сектора (+0), 1 дверь, 0 предупреждений |
| 4. Регистрация карты (см. решения) | Карта видна игре | `load_map` в headless-сценарии без ошибок |
| 5. Сценарий `tests/scenarios/tower1.yml` | Автопроверка | Движение из западной комнаты в восточную; до открытия двери `expect_stop` у двери, после `execute_event` проход открыт; `save_game`/`load_game` сохраняет состояние двери |
| 6. Визуальный прогон `run_game.sh --isolated` | Скриншоты | Текстуры видны, швов и щелей нет |
| 7. Реимпорт с изменённой геометрией | Повторная сборка | Дверь и событие сохранены без ручной правки |

GLB для итерации 1 можно сгенерировать небольшим Python-скриптом без Blender: несколько коробок с UV. Это убирает
зависимость от Blender на первом шаге и даёт воспроизводимый тестовый вход.

## Итерация 2: этаж башни

Центральный зал, 2–3 боковые комнаты, лестница или наклонный пандус на полуэтаж (наклонные полы типов 3/4, как в
сценарии `mm8_party_slopes.yml`), 3–4 `LIGHT_*`, одна `DECOR_*` с событием, один рычаг, открывающий дверь, одно
событие с сообщением и quest bit. Критерии те же плюс подъём по лестнице сценарием `movement_segment`.

## Решения перед стартом

1. **Сборка.** Включить `OPENYAMM_BUILD_EDITOR` и `OPENYAMM_BUILD_TOOLS` в общем `build/` (быстрее, меняет
   конфигурацию для Codex) или собирать в отдельном каталоге (полная пересборка). Сборка возможна только через
   `safe-heavy-run`, запущенный на хосте: внутри песочницы агента он отказывается работать.
2. **Регистрация карты.** Строка в `assets_dev/engine/data_tables/map_stats.txt` меняет существующую таблицу движка.
   Варианты: временная строка с откатом после проверки; или отдельный тестовый мир. Требуется согласование.
3. **Где хранить прототип.** Предлагается `assets_dev/worlds/<test-world>/` или каталог вне `assets_dev`, без коммита до
   отдельного решения. Ресурсы Amber Island в прототип не попадают.

## Необходимые изменения кода (минимум)

| Изменение | Зачем | Размер |
|---|---|---|
| Нет обязательных | Итерация 1 возможна без правок движка, если шаблон сцены подойдёт | — |
| Команда или CLI «новая indoor-карта» | Убрать ручное копирование шаблона | Небольшое, в `editor/document/` |
| Детекция ODM v7 без метки версии | Только для outdoor-карт MMEditor и Amber Island | Небольшое, `OutdoorMapData.cpp:71-89`, плюс тест |

Если на шаге 3 или 5 компилятор не справится, работа останавливается: фиксируется точный блокирующий компонент и
предлагается минимальное исправление, без разработки нового редактора.

## Долгосрочно: локация как проект

```text
locations/<id>/
  source/<id>.blend            архитектура (Blender, Git LFS)
  source/<id>.glb              экспорт (или собирается скриптом из .blend)
  <id>.geometry.yml            метаданные по именам узлов: стабильные id комнат, порталов, механизмов
  <id>.scene.yml               сущности, начальное состояние
  <id>.lua                     события (RegisterEvent)
  dialogues/*.yml              диалоги и условия (внешний редактор → YAML)
  tests/<id>.yml               headless-сценарий
```

- **Реимпорт без потерь:** ключ — имя узла, а не индекс грани. Это уже так устроено в `geometry.yml`; нужно
  правило именования и проверка уникальности (дубликаты комнат компилятор отклоняет).
- **Стабильные ID:** id событий, дверей и сущностей задаются в YAML, а не вычисляются из порядка граней.
- **Сборка:** одна команда `--headless-build-map` и сценарий в CI, без пересборки игры.
- **Диалоги:** внешний визуальный редактор (например, на базе узлов) сохраняет YAML с узлами, условиями (навык,
  характеристика, quest bit) и последствиями; небольшой генератор превращает его в Lua поверх существующих функций
  `evt`, `Question`, `SetQuestBit`, `CheckSkill`. Новый runtime в движке не нужен. Это отдельное исследование.
- **Приключения как наборы контента:** по модели миров OpenYAMM (`assets_dev/worlds/<id>`), с собственным
  диапазоном QBit от 10000 и id-диапазонами, как требует `AGENTS.md`. Amber Island полезен как пример объёма
  (2 outdoor + 6–9 подземелий, 6–12 часов игры), но не как архитектура: его логика построена на хуках памяти
  MMExtension.
