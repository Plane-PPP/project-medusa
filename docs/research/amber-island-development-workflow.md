## 3. Цепочка Blender → MMEditor → игра

### 3.1. Подтверждённые этапы

Описания Dev Stream ([Автор]):

- **07 Oak Hill Cottage**: моделирование дома, второй этаж, крыша, тоннели.
- **08 Texturing Cottage**: ящики, книжные шкафы, вода, первый тест в игре, камины и камень, балки, мебель, пол,
  финальный тест.
- **09 Finishing Cottage Dungeon**: Slicing / Portals, несколько циклов Collision Test / Fix, Portal Bugfix, Sky
  Texture Issue, Texture UV Fix, Making Doors (with issues), Doors Done Properly, Elevator, Chests, Bookcases /
  Winerack, Adding New Monster: Ratman, Adding Level Into the Game.

Пост от 19 Jun 2023 описывает те же этапы: «slicing or dividing levels into smaller rooms», «Collision checks and
fixes to prevent the player from getting stuck», «Pedantic hunt for texture inconsistencies»
([страница 4](https://www.celestialheavens.com/forum/topic?t=17442&start=60)).

### 3.2. Порядок работы

1. **Blender.** Моделируется вся геометрия, сразу с реальными текстурами MM7. Текстура задаётся материалом, имя файла в
   `map_Kd` равно имени bitmap. **[Код]**: `Scripts/Global/Editor Import.lua:21-41`, имя без расширения становится
   именем текстуры. **[Реконструкция]**: что текстуры ставились именно в Blender, следует из видео 08 «Texturing».
2. **Разрезание на комнаты.** Каждый объект или группа `o`/`g` в OBJ при импорте становится отдельной комнатой
   (сектором). **[Код]**: `Editor Import.lua:94-97`, `:245-256`, дубликаты имён отклоняются. Порталы задаются полигонами с
   материалом `_Portal_` в одной из двух комнат (`:184`). Если ручных порталов нет, комнаты с общими вершинами
   соединяются автоматически (`:266-268`, `:332-345`). Невидимые стены задаются материалом `_Invisible_` или
   прозрачным материалом `d < 1` (`:36-37`, `:190`).
3. **Экспорт OBJ из Blender.** Нельзя триангулировать при экспорте (Readme). По умолчанию MMEditor поворачивает оси:
   Y-up в OBJ становится Z-up (`Editor Import.lua:1-8`, `:85-87`), масштаб задаёт `Editor.ImportScale` (`:61`, `:88`).
4. **Импорт в MMEditor**, внутри запущенного `mm7.exe` в окне, `Alt+F1`: Import → «as rooms» или «as objects».
   При импорте вогнутые и изогнутые грани и грани больше чем с 50 вершинами триангулируются, вогнутый портал
   превращается в выпуклую оболочку (`:294-300`), вырожденные грани отбрасываются молча (`:153`). **[Код]**
5. **Настройка в MMEditor**: двери (New Door, Door Shape, `VertexFilter` Free/Grow/Shrink/CheckShift, см.
   `Editor Data.lua:1146-1160`), свойства граней (Event, TriggerByClick), монстры, предметы, сундуки, спрайты,
   источники света, спавны. **[Код]** + Readme.
6. **Компиляция**: per-room BSP (`Editor BSP.lua:409-418`), привязка порталов к комнатам по ориентации
   (`:422-431`), запись `.blv` + `.dlv` (`Editor Data.lua:2095-2174`). **[Код]**
7. **Тест в игре и исправления**: застревания, «липкие места» («sticky places», 21 Feb 2022), щели порталов, UV.
   Видео 09 показывает несколько циклов. **[Автор]**
8. **Подключение к игре**: карта в `new.GAMES.LOD`, строка в `MAPSTATS.TXT`, скрипт `Scripts/Maps/<map>.lua`, переходы
   через `evt.MoveToMap`. **[Код]**

## 4. События и логика

Логика карт написана на Lua MMExtension, а не на EVT. **[Код]**

- `Scripts/Maps/<map>.lua`: `evt.map[N] = function() … end`, `evt.hint[N] = …`, вызовы с именованными таблицами
  (`evt.SetDoorState{Id = 1, State = 2}`), `Game.*`, `Map.*`, `Party.*`, `events.AfterLoadMap`, `vars.*`.
- Самые частые вызовы во всех картах: `evt.SetDoorState` (263), `evt.Cmp` (131), `evt.Set` (112), `evt.Add` (95),
  `evt.HouseDoor` (69), `evt.MoveToMap` (49), `evt.CastSpell` (49), `evt.SetFacetBit` (36), `evt.OpenChest` (33).
- Текст выносится в таблицу `ModTxt` (локализация), квестовое состояние хранится в `vars.QuestsAmberIsland` и
  `vars.MiscAmberIsland`.
- Глобальные механики (наёмники, сложность, улучшенный ИИ) работают как Lua-хуки поверх памяти игры
  (`Scripts/General/Mod*.lua`, `Scripts/Structs/After/*.lua`).

## 6. Совместимость файлов Amber Island с OpenYAMM

| Что | Результат | Метка |
|---|---|---|
| 11 BLV | Совпадают с layout v7 OpenYAMM байт в байт (`IndoorMapData.cpp:175-324`) | [Код]: разбор структуры, не запуск игры |
| 11 DLV | Разбираются до конца при v7-размерах записей | [Код] |
| 4 ODM | Пустое поле версии по смещению 0x40. OpenYAMM считает такой файл **MM8** (`game/outdoor/OutdoorMapData.cpp:71-89`) и читает рельеф со смещения 0xb4 вместо 0xb0. При v7-смещении файл осмыслен (32 259 нормалей, 488 BModels), при v8 получаются 0 моделей. Без исправления геометрия будет потеряна | [Код], без запуска |
| Lua-скрипты | Несовместимы на уровне API: в OpenYAMM `RegisterEvent(id, title, fn)` и позиционные аргументы, проверяемые `luaL_checkinteger` (`game/events/EventRuntime.cpp:8663`). Нет `evt.map[]`, `Game`, `Map`, `mem`, `events` в форме MMExtension | [Код] |
| Таблицы | Формат MMExtension. OpenYAMM ведёт объединённые таблицы MMerge в `assets_dev/engine/data_tables/`, поэтому нужна миграция идентификаторов | [Код] |
| Текстуры и спрайты | Не проверены, LOD не скачаны | [Не установлено] |

Лицензионный вывод сильнее технического: даже при полной совместимости переносить Amber Island в публичный OpenYAMM
нельзя без разрешения автора.

## 7. Выводы для собственного проекта

1. Автор строил подземелья целиком в Blender, включая текстуры, а MMEditor использовал как «компилятор плюс
   расстановщик»: комнаты, двери, объекты, свойства граней. Большая часть времени ушла на исправление коллизий,
   порталов и UV после импорта.
2. Самые дорогие ошибки процесса: потеря свойств граней при повторном импорте, ручное разрезание на комнаты, текстуры
   без поворота и масштаба.
3. В OpenYAMM уже есть аналог этой цепочки с более устойчивыми идентификаторами: glTF с именованными узлами
   `ROOM_`/`PORTAL_`/`MECH_` и метаданные `geometry.yml`. Привязка к имени узла, а не к позиции вершины, решает
   проблему 2.
4. MMEditor требует Windows, `mm7.exe` и патч GrayFace, а созданные им ODM OpenYAMM сейчас прочитает неверно. Брать
   его в основной процесс нецелесообразно. Он полезен как эталон поведения и как способ посмотреть чужие карты.
